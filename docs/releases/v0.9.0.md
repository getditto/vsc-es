**0.9.0 is a private engineering preview.** This release brings the Ditto
SDK 5.1 production-diagnostics surface to Ditto Edge Studio. It is published
as a GitHub Release for internal evaluation and is not published to the VS
Code Marketplace.

## Highlights

- **Portal URL compatibility fix** — Server connections now accept URLs copied
  directly from the Ditto Portal, including the `https://` scheme. Legacy
  host-only saved connections are upgraded automatically before SDK connect.
- **Debug Console** — connect directly to a running Ditto SDK 5.1+ app over its
  `debug_socket` and run live DQL without configuring a separate extension-side
  Ditto connection.
- **System metrics dashboard** — Database Metrics now polls SDK 5.1's
  `system:metrics` virtual collection while visible, accumulating network,
  SQLite, and recovery counters since connect. The dashboard calls out exporter
  or configuration states instead of showing an empty table.
- **ADVISE in Query Editor** — run `ADVISE <SELECT ...>` to see the query plan's
  index recommendations, including the reason and ready-to-run `CREATE INDEX`
  statement. Creating an index confirms first and refreshes the Connections
  tree.
- **5.1 replication/recovery log patterns** — Log Analyzer recognizes metadata
  corruption recovery, consecutive resets, local-trigger resets, and frequent
  post-eviction cleanup, with severity-aware matching and recommendations.

## Changes

### Debug Console

- Added the `Ditto: Open Debug Console` command and a standalone panel for the
  running app's Unix debug socket.
- Supports persistent FIFO-paired multi-query sessions, JSON result rendering,
  DQL errors, connection state, live-mutation warnings, a 64 MiB response-line
  cap, a 10,000-row host-side cap, and safe timeout/disconnect handling.
- The console is available on macOS and Linux; Windows does not provide the
  required Unix debug socket.

### System metrics

- Added a startup-gated `dittoVsce.collectSystemMetrics` setting, enabled by
  default, that enables the SDK exporter before opening Ditto.
- Added flush-aware accumulation: each `system:metrics` read contributes
  deltas to since-connect totals, with polling only while Database Metrics is
  visible.
- Added network DSOQ counters, opened-vs-closed divergence detection, TLV
  version-skew guidance, SQLite fsync/WAL/checkpoint metrics by database label,
  and recovery counters.

### Query diagnostics

- Added host-side ADVISE result extraction and a Query Editor advisory card.
- ADVISE skips the incompatible automatic `PROFILE`/`EXPLAIN` path and supports
  composite index suggestions without reordering their fields.
- Index creation re-checks the active connection after confirmation and uses the
  existing index repository/tree refresh path.

### Log Analyzer

- Added four SDK 5.1 patterns with positive and negative fixtures:
  `replication_metadata_corrupt_recovery`,
  `replication_consecutive_resets`, `replication_reset_local_trigger`, and
  `post_eviction_cleanup_frequent`.
- Added recommendations and level-sensitive matching for the new patterns.

### Quality and tooling

- Added the test injector for repeatable diagnostics demos, including generated
  datasets, a debug socket, and optional metrics export.
- Added broad unit and live offline-SDK coverage for the debug socket,
  `system:metrics`, ADVISE, composite indexes, and the new log patterns.
- Hardened CI/release security checks and added SBOM generation to GitHub
  Releases.

## Known issues

- The Debug Console requires a real Ditto SDK 5.1+ app with `debug_socket`
  enabled; its socket is not available on Windows.
- `system:metrics` is startup-gated. If `dittoVsce.collectSystemMetrics` is
  changed, reconnect the database so the SDK opens with the new setting.
- The new recovery patterns only appear when the underlying SDK condition
  occurs. Use the bundled test injector for a reliable Debug Console and
  metrics demonstration.
