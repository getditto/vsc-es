**0.7.0 is a private engineering preview.** It is not published to the VS Code Marketplace and will not auto-update. Like prior 0.x releases, this build is shared inside Ditto so engineers can keep stress-testing Edge Studio against real apps and tell us what's still rough.

If you're upgrading from 0.6.0, uninstall it first (or disable it while running the dev build) — both versions share the same persistence directory at `~/Library/Application Support/Code/User/globalStorage/ditto.ditto-vsce/dittoData/` and the SDK's working-directory lock will refuse to let two copies open the same database at the same time.

## Highlights

This release adds the **Query Profiler** — a new Profile tab on every Query Editor that captures Ditto's `PROFILE` execution plan and visualises it as either nested operator cards or a top-down boxes-and-lines tree, with per-operator timing, document throughput, and bottleneck highlighting. The feature mirrors the Profile viewer in the SwiftUI Edge Studio app.

It also adds **right-click "Delete Index"** in the Connections tree (one of the first things users have asked for on top of the existing "Add Index" flow), a small accessibility pass on the profile UI so the operator tree is readable in dark themes and the hotspot indicator survives red-green color blindness, and a new **settings cog menu** in every Query Editor that lets developers gate both profiling and metrics collection on or off without touching VS Code's settings UI.

## Changes

### Query Profiler

- **New Profile view tab in the Query Editor.** Sits next to JSON and Table. Renders an execution-plan envelope captured automatically when you run a SELECT on the Local SDK path. Three sub-views:
  - **Header card** with the query (PROFILE prefix stripped for display) and a local-time "captured at" timestamp.
  - **Summary strip** with six cells: Elapsed, Parse, Plan, Result Count, FeatureFlags, QueryType. Times auto-scale (ns / µs / ms) so a 209 ns parse renders as `209 ns` and a 432 ms elapsed renders as `432.43 ms`.
  - **Execution plan** with a Card / Plan sub-toggle. Card mode shows recursive nested operator cards with colored `in / out / exec / recv / send` badges. Plan mode shows the same tree as a top-down boxes-and-lines diagram with SVG connectors and an orange-dashed border on any operator that consumes ≥ 50% of plan CPU work (the bottleneck cue).
- **Automatic on local SELECT.** Runs `PROFILE <query>` transparently, pops the trailing `~request_profile` envelope from the result rows, and parses it into a structured profile. Non-SELECT statements, queries the user already prefixed with `PROFILE`, and HTTP-mode queries are passed through unchanged (PROFILE is local-only for v1).
- **Forgiving parser with false-positive protection.** Tolerates partial envelopes (missing `times`, missing `state`, etc.) and refuses to misclassify a user document that happens to have an `_id` and a `plan` field. The parser requires at least one envelope-only discriminator (`times` / `queryType` / `requestType` / `featureFlags` / `state` / `resultCount` / `text`) before treating a row as a profile.
- **Three empty states** when no profile is available: "Profiling runs on Local only" (HTTP mode), "Profile is only captured for SELECT statements" (non-SELECT), "Run a query to capture a profile" (initial state). Priority order: HTTP > non-SELECT > no-query.
- **Accessibility hardening:**
  - Plan-tree connector lines now use `--vscode-tree-indentGuidesStroke` (VS Code's purpose-built tree connector color) instead of the panel-border color, which was nearly invisible in dark themes.
  - Hotspot boxes pair the orange tint with a **2 px dashed border** so the bottleneck distinction survives deuteranopia / protanopia (red-green color blindness — ~5-8 % of men). The legend mirrors this treatment.
  - Operator stat badges already pair color with a text label (`exec 133.70 µs`), so they're readable under all forms of color blindness.

### Index management

- **Right-click "Delete Index"** on any index in the Connections tree (or click the inline trash icon that appears on hover). Shows a modal confirmation, runs `DROP INDEX IF EXISTS <name> ON <collection>`, and re-hydrates the tree so the index disappears immediately.
- Refuses to fire when you're not currently connected to that database (matches the add-attachment guard pattern).
- Failure surfaces as an error toast and is logged under the `ext:deleteIndex` tag.

### Profiling and metrics gates (settings cog)

- **New cog button** in the Query Editor toolbar (immediately after the Favorite button) opens a popover with two checkboxes: **Capture profiling data** and **Capture query metrics**. Toggling either writes to your user-scope VS Code settings (`dittoVsce.collectProfiling` / `dittoVsce.collectMetrics`) and is reflected instantly in every open Query Editor, the Inspector, and the Connections tree.
- **When profiling is off:** the Profile view-toggle button is hidden, the editor falls back to JSON if you were on Profile, and SELECTs run without the `PROFILE` prefix (no per-query profile overhead).
- **When metrics are off:** the Metrics tab in the Inspector is hidden, the **Query Metrics** row under each database in the Connections tree is hidden, and the EXPLAIN side-trip that `executeQuery` normally fires is skipped (no per-query metrics overhead).
- Settings can also be toggled via VS Code's settings UI or `settings.json` — changes from any source are picked up live.

## Developer-visible changes

- New types: `QueryProfile`, `QueryProfileTimes`, `QueryProfileOperator`, `QueryProfileStats` (`src/ditto/QueryProfile.ts`).
- New parser: `parseProfileItem`, `isSelectStatement`, `alreadyHasProfilePrefix` (`src/ditto/QueryProfileParser.ts`).
- New formatter: `formatNs`, `percentOfTotal` (`src/util/profileTimeFormatter.ts`).
- New Lit components: `<ditto-profile-viewer>`, `<ditto-profile-card-list>`, `<ditto-profile-plan-tree>`, `<ditto-pill>` (the last is reusable across the webview).
- `QueryResultMetadata.profile?: QueryProfile` added — flows through `query.result` IPC, the Inspector's metrics tab, and the Query Metrics ring buffer.
- `CollectionsRepository.dropIndex(name, collection)` mirrors the existing `createIndex` shape.
- 18 new unit tests added; full suite at 37/37 green.

## Known issues

Everything from the 0.6.0 known-issues list still applies. No new known issues are introduced by this release.

- **Intel Mac (`darwin-x64`) and Windows on ARM (`win32-arm64`) are not supported** — the `@dittolive/ditto` SDK does not ship binaries for those targets.
- **No SQLCipher** in this build — Ditto's local store is unencrypted at rest. Avoid pointing it at a Ditto app whose collections contain real customer data.
- **PROFILE is local-only.** HTTP-mode queries do not capture a profile.
- **Pre-release tag suffixes** (`-rc`, `-beta`) are not yet supported by the release workflow — only `v<MAJOR>.<MINOR>.<PATCH>` tags produce releases.
- **No auto-update** — install the new `.vsix` the same way as before.

## Installing locally

Same side-load flow as 0.6.0 — there is no Marketplace install.

1. Scroll down to **Assets** at the bottom of this release page and download the `.vsix` matching your platform:

   | Platform              | Asset                                  |
   | --------------------- | -------------------------------------- |
   | macOS (Apple silicon) | `ditto-vsce-darwin-arm64-0.7.0.vsix`   |
   | Linux (x86_64)        | `ditto-vsce-linux-x64-0.7.0.vsix`      |
   | Linux (ARM64)         | `ditto-vsce-linux-arm64-0.7.0.vsix`    |
   | Windows (x86_64)      | `ditto-vsce-win32-x64-0.7.0.vsix`      |

2. If you have 0.6.0 installed, uninstall it first so the two versions don't fight over the working-directory lock:

   ```bash
   # VS Code
   code --uninstall-extension ditto.ditto-vsce

   # Cursor
   cursor --uninstall-extension ditto.ditto-vsce

   # Google Antigravity
   agy --uninstall-extension ditto.ditto-vsce
   ```

3. Install the new build. UI path is the same in all three editors (Extensions sidebar → `…` → **Install from VSIX…** → pick the downloaded file). CLI path differs by editor:

   ```bash
   # VS Code
   code --install-extension ~/Downloads/ditto-vsce-darwin-arm64-0.7.0.vsix

   # Cursor
   cursor --install-extension ~/Downloads/ditto-vsce-darwin-arm64-0.7.0.vsix

   # Google Antigravity (binary may also be `antigravity` on some builds)
   agy --install-extension ~/Downloads/ditto-vsce-darwin-arm64-0.7.0.vsix
   ```

4. Reload your editor (Command Palette → **Developer: Reload Window**). Your existing connections from 0.6.0 are preserved — they live in `globalStorage`, which the new build reads transparently.

The full guide is in the [README Installation section](https://github.com/getditto/vsc-es#installation).
