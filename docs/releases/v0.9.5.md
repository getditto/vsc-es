# Ditto Edge Studio v0.9.5

This release adds an **embedded MCP (Model Context Protocol) server** so AI
agents can work with your Ditto databases directly through Edge Studio,
splits System Metrics out of Database Metrics into its own screen, and ships
a broad round of pre-release hardening across connections, panels, and
observers.

## Highlights

- **Embedded MCP server for AI agents** — Edge Studio can now expose the
  active Ditto database to MCP clients: GitHub Copilot agent mode picks the
  tools up automatically while the server runs (no setup), and any other MCP
  client can connect at `http://127.0.0.1:65270/mcp` with the snippet from
  **Ditto: Copy MCP Client Config**. The surface matches the SwiftUI Edge
  Studio's MCP server (Streamable HTTP at `/mcp` plus legacy HTTP+SSE), so
  the same client configurations work against both apps.
- **31 tools + 6 read-only `ditto://` resources** — agents can list and
  switch connections, run DQL (with the Query Editor's row caps and
  truncation reporting), explain and profile queries around index changes,
  inspect the schema, manage subscriptions and observers, sample live query
  traffic with a bounded `watch_query`, read presence/sync status and
  metrics, search the Ditto and Log-Analyzer logs, and download attachments
  straight to disk. Point-in-time snapshots are exposed as resources:
  `ditto://schema`, `ditto://peers`, `ditto://sync-status`,
  `ditto://subscriptions`, `ditto://observers`, `ditto://system-metrics`.
- **Security model: off by default, per connection** — the server starts
  only while a connection with **MCP Server** enabled (Edit Configuration →
  Advanced) is active, and stops when you disconnect or switch to an
  unflagged connection. It binds loopback only (`127.0.0.1`/`::1`, port
  65270 — the SwiftUI app uses 65269, so both can run side by side), refuses
  non-loopback `Host` headers (DNS-rebinding), caps requests at 4 MiB, and
  rejects unknown sessions before any tool runs. It is intentionally
  unauthenticated like other local dev tools: while it is enabled, **local
  processes can read and write the connected database** — enable it only on
  connections where that is acceptable. Tool output never contains
  credentials, presence data ships as metadata key counts rather than
  bodies, and attachment downloads are confined to the workspace, extension
  storage, or the OS temp directory with an atomic no-clobber guard.
- **System Metrics is a separate screen** — the `system:metrics` dashboard
  no longer shares the Database Metrics panel. It has its own row in the
  database tree, between Database Metrics and Log Analyzer, and its own panel.
- **Redesigned to match the SwiftUI Edge Studio** — a segment control filters
  the dashboard by namespace (All / Network / Store / Sync / Other), every
  reported metric series renders as its own row, and each row's ⓘ icon
  expands its details (description, kind, unit; histograms also show the
  average and absolute max since connect).
- **Metric search** — a filter box to the right of the segment control
  narrows the full metric list by case-insensitive substring over metric
  names and labels (e.g. `ble` finds every `transport=ble` series), and
  composes with the namespace segments. The Pinned section stays untouched.
- **Pinned metrics** — pin any series from its row to collect it in a
  collapsible **Pinned** section above the segment filter. Pins keep their
  main-list row, render regardless of the namespace filter, persist per
  connection (across panel closes, reconnects, and editor restarts), can be
  reordered by dragging (three-bars handle, iOS/macOS idiom), and can all be
  removed at once with the section's **Clear**.

## Changes

### MCP server

- New per-connection **MCP Server** toggle (Edit Configuration → Advanced,
  default off) and the `dittoVsce.mcpServer.port` machine-scoped setting
  (default 65270; applies immediately — the listener restarts when running).
- New commands: **Ditto: Start MCP Server**, **Ditto: Stop MCP Server**,
  **Ditto: MCP Server Status** (state, URL, session count, last start
  error), and **Ditto: Copy MCP Client Config**. A status-bar item
  (`⎇ plug Ditto MCP :65270`) appears while the server runs and opens the
  status view.
- Copilot agent mode picks up the tools automatically via an MCP server
  definition provider whenever the server is running.
- Stateful sessions: the first request must be `initialize`, afterwards
  clients send the `Mcp-Session-Id` header; requests are capped at 4 MiB,
  and unknown or expired session ids are rejected with 404 before reaching a
  tool, so a client retry after a server restart cannot double-apply a
  mutation. DNS-rebinding protection refuses requests whose `Host` header
  is not the bound loopback address.
- `watch_query` is bounded (max 30 s, 100 events, 200 rows/event) and honors
  client cancellation and session close instead of pinning observers.
- Server lifecycle is logged to the Output channel **and** the Log Analyzer
  — including a dedicated start-failure problem pattern — so "why didn't my
  agent connect?" is answerable in-product.
- Ships an agent skill bundle (`plugins/ditto-edge-studio-vscode`) with a
  scripted acceptance playbook (`docs/MCP_VALIDATION.md`) and a full server
  reference (`docs/MCP_SERVER.md`). Adds `@modelcontextprotocol/sdk` as a
  runtime dependency.

### System Metrics

- Added a **System Metrics** row to the database tree (pulse icon) and the
  `dittoVsce.openSystemMetrics` command. The row sits after Database Metrics
  and before Log Analyzer.
- Added a dedicated System Metrics panel with the same visibility-tied
  polling (every 5 s while the panel is visible) and since-connect totals as
  before. Its Refresh button forces one immediate poll ahead of the cadence.
- The dashboard now lists **all** reported series (previously only curated
  DSOQ/SQLite/recovery keys rendered), filterable by namespace segment, with
  per-row expandable details behind an info icon; the opened-vs-closed
  divergence banner remains.
- Added per-series pinning: a pin glyph on each row toggles membership in the
  pinned set, pushed to the host as a wholesale `sysMetrics.setPins`
  replacement and stored under a per-database `globalState` key.
- Hardened pinning against duplicates: the same series can never appear in
  the pinned section twice — reads, writes, and the webview's incoming state
  all dedupe by series identity.
- Database Metrics is now storage-only: Refresh computes the on-disk
  breakdown and collection payload sizes and no longer touches
  `system:metrics`.
- The Inspector sidepanel shows System Metrics help when the new row or panel
  is focused.
- On a database switch or disconnect, the System Metrics panel closes with
  the other per-database panels so since-connect totals never carry across
  connections.

### Fixes

- Debug Console: clicking **Disconnect** while a connect is still in flight
  now fails fast instead of hanging the panel on a promise that never
  settles.
- Observer editor: saving over a running observer with a query that fails
  the SDK's parser now warns and shows the observer inactive, instead of
  silently stopping event delivery.
- The collections tree now live-updates even if the first load hit a
  transient failure.
- The sidebar recovers from a corrupted stored connection list instead of
  breaking on every render.
- Subscription save and import now report "saved, but could not start on
  this connection" accurately instead of a misleading "save failed" — and
  subscriptions stay saved in that state.
- Database Metrics no longer keeps scanning the old connection's storage
  after a mid-refresh database switch.
- Tree expansion state is no longer lost under rapid expand/collapse.
- The Inspector webview now enforces the same CSP script nonce as every
  other panel (security hardening for the surface rendering the most
  user-controlled JSON).
- MCP server lifecycle: fixed a race where a disposed extension could leave
  a bound listener behind, and a race where concurrent Log-Analyzer tool
  calls could leak a subscription matching every extension log line.

## Known issues

- The Debug Console remains available only on macOS and Linux because it uses
  Unix-domain sockets.
