**0.8.0 is a private engineering preview.** It is not published to the VS Code Marketplace and will not auto-update. Like prior 0.x releases, this build is shared inside Ditto so engineers can keep stress-testing Edge Studio against real apps and tell us what's still rough.

If you're upgrading from 0.7.0, uninstall it first (or disable it while running the dev build) — both versions share the same persistence directory at `~/Library/Application Support/Code/User/globalStorage/ditto.ditto-vsce/dittoData/` and the SDK's working-directory lock will refuse to let two copies open the same database at the same time.

## Highlights

This release adds the **Log Analyzer** — a per-database log triage panel that watches the SDK and extension log streams live, scans every line against a regex catalog of known problem patterns, and surfaces results as severity-ranked counts, three live histograms, and a fully searchable virtualized table with click-to-detail. Inspired by the Python `small_peer_log_parser` support tool — it brings the same pattern-catalog + recommendation approach into the IDE, applied live rather than to uploaded files.

It also adds a **Pattern Editor** for managing the catalog (bundled patterns are read-only; user patterns get full CRUD with live regex validation and a sample-line tester), **user-defined tags** on patterns that surface in the log table and search box, comprehensive **Inspector help docs** for both panels, a fix for **collections-invisible-until-reconnect** on first connect, and a behind-the-scenes **test infrastructure fix** that unmasked 322 silently-skipped tests across the codebase.

## Changes

### Log Analyzer

The Log Analyzer opens per-database from a new **Log Analyzer** row in the Connections tree, between **Database Metrics** and the **Import** divider. The panel is singleton-per-database and closes automatically when the connection disconnects.

- **Per-connection scope** — backfills only from the database's most-recent connect timestamp; doesn't import weeks of rotated log history. A 2-minute connection shows ~2 minutes of data, not 2 weeks.
- **Summary section** (collapsible) — Critical / Errors / Warnings / Problems / Lines counters; detected SDK version; observed logger tags; session time range.
- **Three live histograms** (collapsible):
  - **Log Volume by Level** — stacked bars per time bin (error / warn / info / debug / trace), adaptive bin width that targets ~40 bars regardless of session length.
  - **Problems over Time** — same time axis, colored by max severity in each bin.
  - **Connection Durations** — log-scale bins (`0–1s` / `1–5s` / `5–30s` / `30s–5m` / `5m+`), populated from SDK `physical connection started/ended` log lines, paired by remote peer.
- **Filter tabs** — All / Critical / Errors / Warnings / Problems, each with a live count badge.
- **Free-text search** with 200 ms debounce, case-insensitive substring match against the line's message, tag, and user-applied tags.
- **Virtualized log table** with five columns — Timestamp / Level / Tag / **User Tag** / Message. All but Message are user-resizable via drag handles between headers (default Tag column widened to 220 px because `ext:CollectionsRepository` was getting truncated; minimum-width clamp at 40 px so a column can't be dragged invisible).
- **Line detail drawer** — click any row → right-side flyout shows the selected line broken out as a clean key/value card (Timestamp / Level / Tag / User tags / Message) with horizontal dividers and full word-wrap.
- **Pattern-based problem detection** — every line scanned against the catalog; matches contribute to the Problems tab, Problems-over-Time histogram, and (when the pattern sets a `user_tag`) the User Tag column.
- **Bundled catalog** ships with 9 signatures for known Ditto issues — deadlocks (critical + warning), expired/early certificates, authentication failures, query-too-big, connection-incomplete, OOM kills, segfaults.

### Pattern Editor

A separate global webview (opened via the **⚙ Patterns** toolbar button in the Log Analyzer, or **Manage Log Patterns** in the global Logging sidebar) for managing the catalog.

- **Bundled patterns** are listed with a 🔒 lock icon and no edit/delete affordance. Updates ship via extension releases.
- **User patterns** support full add / edit / delete with:
  - Live regex validation (Save disabled until the regex compiles)
  - Severity (1–5), required Recommendation, optional Level filter (exact match), optional Tag filter (regex against the line's existing tag)
  - **User tag (optional)** — a label *written onto* matching lines, distinct from Tag filter (which *matches against* the existing tag)
  - **Test line** field to verify the regex against a sample log line without saving
- **Bundled-key collision** is blocked at both the form layer ("Collides with bundled key" inline error) and the storage layer (`PatternStore.delete()` rejects bundled keys server-side as defense in depth).
- User patterns persist to `<globalStorage>/log-analyzer/user_patterns.json` by default. The `dittoVsce.logAnalyzer.customPatternsFile` setting lets you point at a different path (e.g. inside a project repo for version control). Hot-reloads on file change or setting change — any open Log Analyzer picks up the new pattern immediately.

### User-defined tags

A new `user_tag` field on patterns labels every matching line with a semantic category. Surfaces in two places:

- The **User Tag column** in the log table (purple chips, comma-separated when multiple patterns labeled the same line — sorted and deduped)
- The **search box's haystack** — typing the user tag in Search filters to lines that carry it

This is how you build semantic categories on top of the SDK's literal tag (`sdk` / `ext:Foo`). E.g. a pattern that matches DQL index lifecycle and statement-abort lines with `user_tag: query` lets you type `query` in Search and see only those lines.

### Inspector docs

Two new comprehensive help documents that render in the Ditto Inspector (secondary sidebar) when the corresponding panel has focus:

- **`logAnalyzer.md`** — every section, every control, search semantics, lifecycle, common workflows, troubleshooting.
- **`patternEditor.md`** — bundled vs user patterns, every form field with examples, the new `user_tag` field contrasted with `tag_filter`, storage location + `customPatternsFile` setting, save flow, common workflows, troubleshooting.

Both follow the same fetch + injected-HTML pattern every other Inspector doc uses (CSP-safe via `asWebviewUri`, no iframes). The panels' `onDidChangeViewState` handlers re-assert the active feature on focus so the Inspector re-renders the right docs after you've drifted to a different panel.

### Tree fix: collections appear on first connect

The Connections tree previously failed to show a database's collections (and its Indexes row) on the **first** connect after the Extension Host opened. Disconnect + reconnect made them appear. Root cause: the auto-expand `treeView.reveal(database, { expand: 2 })` fired before `collectionsRepo.load()` completed; the late-arriving collection rows weren't surfaced because VS Code doesn't reliably re-render children of a node revealed in the same lifecycle tick. Fix: on the first-connect path, set up a one-shot listener that re-issues the reveal once collections actually arrive. Reconnect already had a parked-retry mechanism (via the `restoreExpansion` branch); this commit adds the same shape to the first-connect path.

### Test infrastructure fix (and the 322 tests that came back)

The repo's `npm test` runner was **silently swallowing every test** in worker isolation. Root cause: `tsx` 4.x registers via Node's synchronous `module.registerHooks()` API (Node 22.16+), which preempted our async `module.register()` hook for the vscode-stub resolver. Every test file failed to load in workers, but the failure was reported as "1 passing test per file" — so the runner appeared green with 39 tests passing when in reality 322 individual tests were silently skipped.

Fix: switched the vscode-stub resolver to use `registerHooks` too. Result: **322 tests came back** across the codebase, with the Log Analyzer work contributing ~85 new ones on top. The catch surfaced two real bugs in the new code (pattern catalog overlap + a regex that couldn't match its own test input) before they shipped — both were unmasked by the runner fix and fixed in the same release. CI's green signal is now real.

### Other Log Analyzer polish

- **Connection Timeline widget removed.** The per-peer SVG lane chart that v0.8.0 originally shipped was unreadable (label collisions, no clear visual hierarchy) and duplicated what Presence + Peer Listing already convey better. Connection Durations stays because that's information you can't get from the existing peer panels.
- **Resizable columns** — the original fixed-width grid truncated `ext:CollectionsRepository` and any other ext-tagged line. Drag handles between header cells now let the user resize the Timestamp / Level / Tag / User Tag columns. Widths persist for the panel's lifetime.
- **Tag filter UX clarified** — the "Tag filter regex (optional)" label was misleading users (they thought typing `query` would apply that label). Renamed to "Tag filter — regex matched against the line's tag", added an explainer with examples (`^sdk$`, `^ext:`), and clarified explicitly that this is **not** a label applied to matching lines (the new `user_tag` field is, see above).
- **Line detail drawer simplified** — the original drawer rendered ±5 lines of borderless context as a tall stack with no clear boundaries. Replaced with a clean key/value layout for just the selected line; the `beforeLines` / `afterLines` props stay on the IPC for backward compatibility but are no longer rendered.

### Behind the scenes

- **`Logger` extra sinks** — added an additive `extraSinks?: Sink[]` option to `createLogger` so the Log Analyzer can tap into the existing logging pipeline alongside `ChannelSink` and `FileSink`. Sink throws are isolated — a buggy analyzer can't break the Output Channel or the rotating log file.
- **Pattern engine with merge + validation** — `PatternEngine` loads the bundled catalog, merges user patterns on top (keys override), compiles each entry's regex with case-insensitive flag, validates severity range + non-empty recommendation. Invalid entries are skipped with a warning; the rest still load.
- **Golden fixture harness** — every bundled pattern requires a paired `.txt` fixture and `.expected.json` listing the keys it should match. Adding a new pattern without a fixture **fails the test suite**. The trust test caught one catalog overlap during development (deadlock_critical vs deadlock_warning both firing on the same line because `level_filter` had at-least semantics; switched to exact match).
- **Observers polish** (several follow-up fixes from the v0.7.0 Observers feature) — proper teardown on lifecycle change, scoped panel disposal, Differ reset, dead IPC + dead memory cleanup, ObserverStore lifecycle cleanup, observer panel ordering moved below collections in the tree.
- **Strict TypeScript** — enabled `noUnusedLocals` / `noUnusedParameters`. Cleared all the unused-import warnings CodeQL flagged.
- **Security** — patched a `serialize-javascript` transitive dependency via npm override.

## Known issues

- **`DatabaseTreeProvider.test.ts` has 5 failing tests** — pre-existing breakage that was masked by the broken test runner. They fail with `TypeError: Cannot read properties of undefined (reading 'getConfiguration')` because the vscode-stub doesn't yet shim `workspace.getConfiguration`. Unrelated to the new Log Analyzer work; will be cleared in a follow-up.
- **Line detail drawer doesn't expose context lines** — by deliberate UX design after user feedback (the previous "±5 lines" rendering was too cluttered). If the developer needs surrounding context, they can scroll the log table directly. The IPC still carries `beforeLines` / `afterLines` so future re-additions don't churn the protocol.
- **No scroll-loading on the log table** — refining your search or filter is currently the way to surface lines beyond the first 1,000 in the current view. The shown/total indicator next to the search box tells you how much was paged.

## What we want feedback on

- **Log Analyzer scope** — is "since this connection's most-recent connect" the right backfill window, or do you sometimes need to see logs from before a reconnect cycle?
- **Pattern catalog coverage** — what known-bad signatures should we ship in the bundled catalog beyond the 9 we currently have? File issues with the regex + an example line and we'll add them.
- **User tags** — does the column + search-box approach feel right, or would a dedicated user-tag filter tab/dropdown be more useful?
- **Histogram bin widths** — adaptive width targets ~40 bars; does that feel right across short (minutes) and long (hours-long) sessions?
- **Pattern Editor UX** — is the distinction between Tag filter and User tag clear in the form, or do you still find yourself confused by which is which? (The help text in the form is the explicit attempt to clarify; tell us if it's not enough.)
- **Inspector help docs** — too long? Right length? Are there workflows you'd add to the "Common workflows" sections?
- Everything else from the 0.7.0 feedback list still applies.

File issues at <https://github.com/getditto/vsc-es/issues>. Tag them with `v0.8.0`.
