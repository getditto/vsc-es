# Ditto Edge Studio v0.9.6

This release moves the extension to **Ditto SDK 5.2.0** and surfaces its
headline diagnostics features: dial9 support-bundle collection, SDK log
export, the new `ditto.query.*` system metrics, and correct rendering of the
SDK's gauge metrics. Query profiling renders the new SDK 5.1/5.2 plan fields.
It also fixes sync and HTTP-mode queries against self-managed (plain-HTTP)
Ditto Servers.

## Highlights

- **Sync against a self-managed (plain-HTTP) Ditto Server now works** — the
  SDK seeds its sync websocket URL by force-upgrading the server URL's
  scheme to `wss://`, so a Big Peer serving plain HTTP received a TLS
  ClientHello on a plaintext port: the server logged `\x16\x03\x01…` 400s
  every few seconds, sync never established, `system:data_sync_info` stayed
  empty, and the Big Peer never appeared in the Presence Graph — while auth
  and the REST API kept working, which made it look like a server problem.
  Edge Studio now pins the websocket URL with the scheme matched to the
  configured server URL (`http` → `ws`, `https` → `wss`). Cloud URLs are
  unaffected: the pin yields the same value the SDK would have derived.
- **HTTP-mode queries against a plain-HTTP Ditto Server now work** — the
  HTTP API call had the same TLS-to-plaintext problem from the other
  direction: it always used `https://`, so a query against a plain-HTTP Big
  Peer died in the SSL handshake ("wrong version number") even with **Allow
  untrusted certificates** checked (that flag only skips certificate
  verification; it cannot downgrade TLS to plaintext). The HTTP API now
  follows the server URL's scheme: `http://…` → plain HTTP, anything else →
  HTTPS. Plaintext calls to a non-loopback host log a warning, since the
  bearer key crosses the network unencrypted.
- **Support bundle collection (dial9)** — **Ditto: Collect Support Bundle
  (dial9)…** captures the SDK's diagnostic bundle over the active
  connection — Tokio task traces (`dial9/dial9.bin.gz`), SDK logs, and
  store diagnostics — and saves it as a single `.tar.gz` ready to attach
  to a Ditto support ticket. For a slow-query investigation, run the query
  first so the trace window covers it. Mirrors the DQL benchmark harness's
  `collect-support-bundle.py` flow (`EXECUTE FUNCTION
  system_request_support_bundle()` → `system:support_bundles` → attachment
  fetch → gzip).
- **Bug-report export is now one zip** — **Ditto: Export Logs for Bug
  Report…** now packs the application log AND an SDK support bundle
  (`EXECUTE FUNCTION system_request_support_bundle()`, new in SDK 5.2.0)
  into a single `.zip` saved where you choose, with a `README.txt` inside
  recording the extension/SDK/VS Code versions and exactly what the archive
  contains. With no active connection — or if bundle collection fails (the
  SDK rate-limits requests to ~3 per 10 minutes) — the export still
  succeeds with the application log alone and the README says why the
  bundle is missing. (Previously the command only opened the log in an
  editor tab.)
- **SDK log export** — **Ditto: Export SDK Logs (gzip)…** writes the Ditto
  SDK's own internal ring-buffer logs (Debug level and up, ~15 MB / 15-day
  retention, independent of the configured SDK log level) to a compressed
  `.jsonl.gz` file via the SDK 5.2 `Logger.exportToFile` API.
- **System Metrics: gauges and the Query namespace** — SDK 5.2's new gauge
  metrics (peer discovery, `network.connections`, `quic.path.rtt/mtu`,
  AWDL interface status, `phy.last_*_at` activity timestamps) now render
  their absolute current value instead of a misleading running sum of
  deltas; epoch-timestamp gauges render as an age ("12s ago"); falling
  gauges show a red ▼ delta. `ditto.query.*` series get their own **Query**
  segment in the namespace filter.
- **System Metrics: every metric under exactly one topic** — the namespace
  filter is rebuilt around the SDK's full metric taxonomy (verified against
  the SDK's metric declarations): **Discovery, Network, Sync, Transport,
  Store, Query,** and a new **Peer** segment, plus **All**.
  Series that previously piled into "Other" — the diffcaster mesh, the
  RIBLT sketch, presence, the sync byte stream, the multicast (NORM)
  transport and its attachment mover, the per-protocol transports, blob
  storage tiers — now land in the topic that owns them, and each series
  appears in exactly one segment. The old **Other** segment is gone: the
  only unrouted series are the metrics pipeline's own telemetry, which
  stay visible under **All**.
- **System Metrics: one row per metric** — the SDK emits a labelled metric
  as an unlabelled aggregate row plus one row per label combination (e.g.
  `small_peer_info.write_store_duration_secs` appeared twice; the SQLite
  backend metrics appeared once bare and once per database role), so the
  same key listed multiple times. The panel now shows only the aggregate
  row — the running total across all label sets — so each key lists once.
  Label-only metrics (which have no aggregate row) are unaffected and still
  show every series. The dsoq connection-leak banner no longer
  double-counts opened/closed totals.
- **System Metrics: a legible segment control** — the topic strip was
  squeezed into a fixed 320px, which left ~35px per button with no padding
  ("Discovery" and "Transport" were unreadable) and let the search box
  overlap it on a narrow panel. The strip now sizes to its content with real
  padding, and both the filter row and the segment box wrap — the search
  box drops to its own line and the segment buttons reflow onto extra rows,
  so every topic stays clickable at any panel width.
- **System Metrics: alphabetical master list** — the metric list is sorted
  by metric name, so a new series no longer lands wherever the SDK happened
  to report it. Pinned metrics keep the order you dragged them into.
- **Application log retention is now under your control** — the extension
  still rotates the application log (5 MB per file, 5 backups), but the
  limits are now settings you can change (`dittoVsce.logMaxMegabytes`,
  `dittoVsce.logRetainFiles`), applied immediately without a reload, and
  rotated backups older than `dittoVsce.logMaxAgeDays` (default 14 days) are
  pruned when the extension starts. **Ditto: Clear Application Log…** — also
  a row in the **Logging** panel — deletes the whole log set on demand after
  a confirmation. The defaults are unchanged, so an existing install behaves
  exactly as before until you change a setting.
- **Richer query profiling** — the Profile views render the SDK 5.1/5.2
  plan fields: `stor` (time blocked on the store backend), scheduler
  `yields`, `documentsSkipped`, and JOIN inner subplans (`nlJoin.inner`)
  as labeled nested subtrees, included in bottleneck highlighting.

## Changes

- Bumps `@dittolive/ditto` from 5.1.0 to `5.2.0`.
- Bumps `@modelcontextprotocol/sdk` from 1.30.0 to 1.32.2 and `zod` from
  3.25.76 to 4.6.7 to pick up published security fixes for the MCP server
  surface (the SDK's OAuth/redirect/body-size advisories and zod's
  oversized-collection advisory). The MCP tool set, names, and input
  schemas are unchanged.
- Startup-gated system parameters now flow through the SDK 5.2
  `DittoConfig.systemParameters` constructor argument (previously the
  metrics exporter was enabled by flipping an environment variable around
  `Ditto.open`). No user-visible change; `dittoVsce.collectSystemMetrics`
  behaves as before.
- New commands: **Ditto: Collect Support Bundle (dial9)…**, **Ditto:
  Export SDK Logs (gzip)…**, **Ditto: Clear Application Log…**.
- The System Metrics namespace filter is rebuilt so every series routes to
  exactly one of **Discovery, Network, Sync, Transport, Store, Query,** or
  **Peer**. Sync covers the replication engine plus the
  diffcaster mesh, RIBLT, presence, and the sync stream; Transport covers
  the multiplexer, the multicast (NORM) transport and attachment mover, and
  the per-protocol transports; Store covers the storage engine, store API,
  small-peer-info writes, and blob storage tiers; **Peer** is a new segment
  for peer identity and attachment P2P transfer. The **Other** segment is
  removed — unrouted series (the metrics pipeline's own telemetry) stay
  visible under **All**.
- The System Metrics **Query** segment catches both the OTLP series
  (`ditto.query.*`, SDK 5.2+) and the legacy `dql.*` series the SDK
  dual-emits alongside them (`dql.requests` ↔ `ditto.query.requests`).
- The System Metrics panel collapses each labelled metric to its unlabelled
  aggregate row, so a key lists once instead of once per label combination;
  label-only series are never dropped.
- **Ditto: Export Logs for Bug Report…** now saves a single zip — the
  application log plus the SDK support bundle and a `README.txt` manifest —
  instead of opening the log in an editor. It degrades to a log-only zip
  (with the reason in the README) when no database is connected or bundle
  collection fails. The zip writer is a small in-house implementation
  (`src/bugreport/zip.ts`) — no new dependency.
- New settings for application-log retention: `dittoVsce.logMaxMegabytes`
  (default 5), `dittoVsce.logRetainFiles` (default 5), and
  `dittoVsce.logMaxAgeDays` (default 14, `0` disables age-based pruning).
  The size and retain-count settings apply live; age pruning runs at
  activation.
- The **Logging** panel gains a **Clear Application Log…** row.
- The application log's rotation now shifts each backup at most once per
  write. Previously an oversized write could rotate repeatedly, churning the
  backup set (`.1` → `.2`) and dropping the oldest backup — silently
  discarding log history.
- The System Metrics segment control sizes to its content and wraps, and
  the master list is sorted alphabetically by metric name (pinned metrics
  keep their drag order).

## Requirements

- Ditto SDK 5.2.0 (bundled). Support bundles and SDK log export
  require SDK 5.2; gauge/query metrics appear only when the connected SDK
  reports them.

## Known issues

- The support-bundle flow is rate-limited by the SDK (~3 requests per 10
  minutes per store) — wait and retry when the error surfaces.
- The reliable UDP multicast transport that the Swift and Android Edge
  Studio apps expose (enabled / group address / port / interface) has no
  JavaScript binding in SDK 5.2.0, so Edge Studio does not expose it yet.
  The underlying engine ships in the bundled SDK binary, but the JS API
  cannot enable it; tracked separately.
