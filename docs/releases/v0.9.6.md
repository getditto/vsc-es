# Ditto Edge Studio v0.9.6 (draft)

This release moves the extension to **Ditto SDK 5.2.0** (`5.2.0-preview.5`)
and surfaces its headline diagnostics features: dial9 support-bundle
collection, SDK log export, the new `ditto.query.*` system metrics, and
correct rendering of the SDK's gauge metrics. Query profiling renders the
new SDK 5.1/5.2 plan fields.

## Highlights

- **Support bundle collection (dial9)** — **Ditto: Collect Support Bundle
  (dial9)…** captures the SDK's diagnostic bundle over the active
  connection — Tokio task traces (`dial9/dial9.bin.gz`), SDK logs, and
  store diagnostics — and saves it as a single `.tar.gz` ready to attach
  to a Ditto support ticket. For a slow-query investigation, run the query
  first so the trace window covers it. Mirrors the DQL benchmark harness's
  `collect-support-bundle.py` flow (`EXECUTE FUNCTION
  system_request_support_bundle()` → `system:support_bundles` → attachment
  fetch → gzip).
- **SDK log export** — **Ditto: Export SDK Logs (gzip)…** writes the Ditto
  SDK's own internal ring-buffer logs (Debug level and up, ~15 MB / 15-day
  retention, independent of the configured SDK log level) to a compressed
  `.jsonl.gz` file via the SDK 5.2 `Logger.exportToFile` API.
- **System Metrics: gauges and the Query namespace** — SDK 5.2's new gauge
  metrics (peer discovery, `network.connections`, `quic.path.rtt/mtu`,
  AWDL interface status, `phy.last_*_at` activity timestamps) now render
  their absolute current value instead of a misleading running sum of
  deltas; epoch-timestamp gauges render as an age ("12s ago"); falling
  gauges show a red ▼ delta. `ditto.query.*` series get their own **Query**
  segment in the namespace filter.
- **Richer query profiling** — the Profile views render the SDK 5.1/5.2
  plan fields: `stor` (time blocked on the store backend), scheduler
  `yields`, `documentsSkipped`, and JOIN inner subplans (`nlJoin.inner`)
  as labeled nested subtrees, included in bottleneck highlighting.

## Changes

- Bumps `@dittolive/ditto` from 5.1.0 to `5.2.0-preview.5`.
- Startup-gated system parameters now flow through the SDK 5.2
  `DittoConfig.systemParameters` constructor argument (previously the
  metrics exporter was enabled by flipping an environment variable around
  `Ditto.open`). No user-visible change; `dittoVsce.collectSystemMetrics`
  behaves as before.
- New commands: **Ditto: Collect Support Bundle (dial9)…**, **Ditto:
  Export SDK Logs (gzip)…**.

## Requirements

- Ditto SDK 5.2.0-preview.5 (bundled). Support bundles and SDK log export
  require SDK 5.2; gauge/query metrics appear only when the connected SDK
  reports them.

## Known issues

- None specific to this release. The support-bundle flow is rate-limited
  by the SDK (~3 requests per 10 minutes per store) — wait and retry when
  the error surfaces.
