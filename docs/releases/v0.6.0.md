**0.6.0 is a private engineering preview.** It is not published to the VS Code Marketplace and will not auto-update. Like 0.5.0, this build is shared inside Ditto so engineers can keep stress-testing Edge Studio against real apps and tell us what's still rough.

If you're upgrading from 0.5.0, uninstall it first (or disable it while running the dev build) — both versions share the same persistence directory at `~/Library/Application Support/Code/User/globalStorage/ditto.ditto-vsce/dittoData/` and the SDK's working-directory lock will refuse to let two copies open the same database at the same time.

## Highlights

This release is a bug-fix release focused on **Small Peers Only** mode. 0.5.0 shipped with a broken offline path: connecting to a small-peer-only database with a shared key produced an "activation" error on first try and a "File already locked" error on every retry until the editor was restarted ([#2](https://github.com/getditto/vsc-es/issues/2)). 0.6.0 fixes that and tightens a related class of locking bug.

## Changes

- **Small Peers Only connections work end-to-end.** Both the offline license token and the optional shared secret key are now passed through to the SDK before sync starts. ([#2](https://github.com/getditto/vsc-es/issues/2))
  - The Offline Token from the form is now applied via `setOfflineOnlyLicenseToken()` before `sync.start()` — eliminates the *"Sync could not be started because Ditto has not yet been activated"* error.
  - The Shared Secret Key from the form is now passed as `privateKey` on the `smallPeersOnly` config — previously this field was collected but silently dropped.
- **Failed connects no longer leak the working-directory lock.** If anything between `Ditto.open()` and a fully-attached session throws, the partially-opened SDK instance is now closed in the catch (10s bounded), releasing `__ditto_lock_file` so the next retry doesn't fail with *"File already locked"* until VS Code is restarted.
- **Clearer error message for genuine lock collisions.** When another live process holds the working-directory lock (for example, a second VS Code window pointing at the same connection, or the marketplace 0.5.0 build running side-by-side with a dev host), the SDK's terse *"File already locked"* is now translated into an actionable message naming the persistence directory and suggesting which windows to close.
- **Duplicate Database IDs are now blocked at save time.** The Register/Edit Database form rejects a save (and `ConfigStore` rejects the underlying write) if another connection already uses the same Database ID. This stops users from accidentally creating two records that point at the same logical database.

## Known issues

Everything from the 0.5.0 known-issues list still applies. No new known issues are introduced by this release.

- **Intel Mac (`darwin-x64`) and Windows on ARM (`win32-arm64`) are not supported** — the `@dittolive/ditto` SDK does not ship binaries for those targets.
- **No SQLCipher** in this build — Ditto's local store is unencrypted at rest. Avoid pointing it at a Ditto app whose collections contain real customer data.
- **Pre-release tag suffixes** (`-rc`, `-beta`) are not yet supported by the release workflow — only `v<MAJOR>.<MINOR>.<PATCH>` tags produce releases.
- **No auto-update** — install the new `.vsix` the same way as before.

## Installing locally

Same side-load flow as 0.5.0 — there is no Marketplace install.

1. Scroll down to **Assets** at the bottom of this release page and download the `.vsix` matching your platform:

   | Platform              | Asset                                  |
   | --------------------- | -------------------------------------- |
   | macOS (Apple silicon) | `ditto-vsce-darwin-arm64-0.6.0.vsix`   |
   | Linux (x86_64)        | `ditto-vsce-linux-x64-0.6.0.vsix`      |
   | Linux (ARM64)         | `ditto-vsce-linux-arm64-0.6.0.vsix`    |
   | Windows (x86_64)      | `ditto-vsce-win32-x64-0.6.0.vsix`      |

2. If you have 0.5.0 installed, uninstall it first so the two versions don't fight over the working-directory lock:

   ```bash
   # VS Code
   code --uninstall-extension ditto.ditto-vsce

   # Cursor
   cursor --uninstall-extension ditto.ditto-vsce

   # Google Antigravity
   agy --uninstall-extension ditto.ditto-vsce
   ```

3. Install the new build. UI path is the same in all three editors (Extensions sidebar → `…` → **Install from VSIX…** → pick the downloaded file). CLI path differs by editor:

   ```bash
   # VS Code
   code --install-extension ~/Downloads/ditto-vsce-darwin-arm64-0.6.0.vsix

   # Cursor
   cursor --install-extension ~/Downloads/ditto-vsce-darwin-arm64-0.6.0.vsix

   # Google Antigravity (binary may also be `antigravity` on some builds)
   agy --install-extension ~/Downloads/ditto-vsce-darwin-arm64-0.6.0.vsix
   ```

4. Reload your editor (Command Palette → **Developer: Reload Window**). Your existing connections from 0.5.0 are preserved — they live in `globalStorage`, which the new build reads transparently.

The full guide is in the [README Installation section](https://github.com/getditto/vsc-es#installation).

## What we want feedback on

- **Small Peers Only** — does the offline + shared-key path now connect first try and stay connected across reconnects?
- **Duplicate-ID guard** — the new save-time check is intentionally strict (trim-equal). If you have a legitimate workflow where two records *should* share a Database ID, tell us — we'd rather hear about it than ship a constraint that's wrong for real usage.
- **Lock-collision messaging** — if you do hit the "working directory is locked" error, was the message enough to figure out which window or process to close?
- Everything else from the 0.5.0 feedback list still applies — onboarding, DQL Query Editor, Peer presence view, missing features, editor parity.

File issues at <https://github.com/getditto/vsc-es/issues>. Tag them with `v0.6.0`.
